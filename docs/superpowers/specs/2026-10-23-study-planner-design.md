## 0. 한눈에 보기

> **산 문제집과 과외 숙제를 넣으면, 시험일(또는 정한 날)까지 하루에 풀 페이지를 정해 주고,
> 밀리면 남은 날에 다시 나눠 주는 도우미.** 틀린 문제·외울 것은 정해진 간격으로 다시 보게 한다.

매일 쓰는 흐름은 이것 하나다.

```
앱 열기 → 「오늘」 화면: 과외 숙제 → 문제집 오늘 분량 → 오늘 복습할 오답·카드
        → 다 풀면 체크(또는 「p.41까지 풀었어요」) → 틀린 문제 번호 적기
        → 내일 분량은 자동으로 맞춰짐
```

### 단계

| 단계 | 내용 | 이 문서에서 |
|---|---|---|
| **1단계** | 문제집 계획 · 과외 숙제 · 「오늘」 화면 · 기기 간 동기화 | 자세히 (바로 만들 것) |
| **2단계** | 오답 노트 + 다시 풀기 일정 · 암기 카드 · **영단어**(단어장·단어 시험·모르는 단어, 카드·객관식) | 자세히 |
| **3단계** | 공부 타이머 · 공부 시간 기록 | 자세히 |
| **4단계** | 할 일 · 습관 관리 | 큰 틀만 (그때 따로 설계) |

각 단계는 끝날 때마다 배포해서 바로 써 보고, 써 본 느낌으로 다음 단계를 고친다.

## 1. 목적과 근거

### 1.1 사용자가 원하는 것 (대화에서 정한 것)

- 할 일·습관보다 **공부 기능을 먼저**. 이 사이트 안에 넣는다.
- **휴대폰 + 컴퓨터 둘 다**에서 같은 내용을 본다.
- **산 문제집을 넣으면** 시험 범위·기간에 맞춰 **페이지 단위로 하루 분량**을 정해 준다.
- 문제집 넣기: **목차 직접 입력(기본) + 목차 사진 읽기(보조)** 둘 다.
- 밀리면 **남은 날에 자동 재분배**.
- 조건: **쉬는 요일**, **특정 날짜 빼기**, **과외 있는 날은 적게**.
- **과외 숙제는 따로**: 마감은 **다음 수업일**.
- 오답 노트, 암기 카드, 타이머·기록, 목표·D-day 도 원함 (2·3단계).
- **영단어**: 출처는 **갖고 있는 단어장 · 학교·학원 단어 시험 · 모르는 단어 모으기**, 넣기는 **단어장 PDF 파일(기본) · 붙여넣기 · 단어장 사진 · 단어만 쓰면 뜻 자동**, 외우기는 **카드 넘기기 · 객관식 퀴즈** (2단계, §9.4~9.9).

### 1.2 설계의 바탕이 된 학습 연구

Dunlosky, Rawson, Marsh, Nathan, Willingham (2013), *Improving Students' Learning With Effective Learning Techniques*, Psychological Science in the Public Interest 14(1).
이 리뷰는 10가지 공부법 중 **연습 시험(스스로 떠올리기)** 과 **분산 연습(간격을 두고 나눠 하기)** 을 효과가 큰 것(high utility)으로,
**다시 읽기·형광펜** 을 효과가 작은 것(low utility)으로 평가했다.

이 앱에 옮긴 것:
- 문제집을 **매일 조금씩 나눠** 풀게 한다 (몰아서 하지 않게).
- 틀린 문제·암기 카드는 **답을 가리고 먼저 떠올리게** 하고, **간격을 늘려 가며** 다시 보게 한다.
- 통계·꾸미기는 최소로: 「얼마나 오래 앉아 있었나」보다 「오늘 할 것을 했나」를 앞에 둔다.

### 1.3 성공 기준

1. 문제집 하나를 넣고 계획을 만드는 데 **2분 이내** (목차 붙여 넣기 기준).
2. 앱을 열면 **첫 화면에서 오늘 할 것 전부**가 보이고, 체크까지 **누르기 1~2번**.
3. 하루 이틀 밀려도 사용자가 아무것도 안 해도 **다음 날 분량이 맞게** 바뀐다.
4. 폰에서 체크한 것이 PC 를 열면 **몇 초 안에** 보인다 (로그인했을 때).
5. 로그인 안 해도, 인터넷이 끊겨도 (이미 한 번 연 기기라면) 쓸 수 있다.

### 1.4 하지 않는 것 (이번 설계 범위 밖)

- 문제집 목차를 인터넷에서 자동으로 찾아오기: 믿을 만한 공개 자료가 없어 지어낸 목차가 들어갈 위험이 있다.
- 휴대폰 푸시 알림(앱을 닫아도 오는 알림): 서버에서 알림을 보내는 별도 장치가 필요하고, 기기마다 동작이 달라 1~3단계에서는 뺀다. 4단계에서 다시 검토.
- 선생님(과외 선생님)이 직접 숙제를 넣는 기능: 다른 사람 계정과 공유하는 구조가 필요하다. 나중에 원하면 따로 설계.
- AI 가 카드·문제를 만들어 주기: API 사용료·키 설정이 필요. 기본 기능을 써 본 뒤 결정.

## 3. 날짜를 다루는 규칙 (모든 기능의 바탕)

- **「하루」의 시작 시각을 설정으로 둔다. 기본 새벽 4시.**
  밤 12시가 넘어서 공부해도 「어제」 분량으로 친다. (설정에서 0~6시 중 고름)
- 날짜는 **그 기기의 시간대** 기준 `YYYY-MM-DD` 글자로 저장한다. 시각(밀리초)은 「언제 고쳤나」에만 쓴다.
- 요일: 0=일 … 6=토.
- 날짜 계산은 한 파일(`dates.ts`)에만 두고 시험(test)으로 확인한다: 월말·윤년(2028-02-29)·연말을 넘는 경우.

## 4. 문제집

### 4.1 문제집 정보

| 항목 | 예 | 필수 |
|---|---|---|
| 이름 | 쎈 수학 상 | ✔ |
| 과목 | 수학 (과목 목록에서 고르거나 새로 만듦) | ✔ |
| 목차 | 단원 이름 + 시작~끝 페이지 (여러 개) | 목차 또는 총 페이지 중 하나 |
| 총 페이지 | 1-240 | 〃 |
| 색 | 과목 색을 따라감 | |

### 4.2 목차 직접 입력

입력 칸 하나에 한 줄씩 붙여 넣는다. 읽는 규칙:

```
1. 집합 12-30          → 단원 「1. 집합」, 12~30쪽
2 명제 31~52           → 단원 「2 명제」, 31~52쪽
Ⅲ. 함수 ........ 53    → 단원 「Ⅲ. 함수」, 53쪽부터 (끝은 다음 단원 시작 - 1)
부록 200               → 단원 「부록」, 200쪽부터
1-240                  → 단원 없이 1~240쪽
```

- 줄 끝의 숫자를 페이지로 본다. `a-b`, `a~b`, `a – b`(여러 종류의 줄표), `a ~ b` 모두 범위.
- 숫자가 하나뿐이면 「시작 페이지」로 보고, 끝은 **다음 줄의 시작 − 1**, 마지막 줄은 **총 페이지(물어봄)**.
- 점선(`....`), 가운뎃점, 여러 칸 띄움은 지운다.
- **읽은 결과를 표로 바로 보여 주고**, 칸마다 고칠 수 있다. 이상한 줄(페이지를 못 찾음, 범위가 뒤집힘, 앞 단원과 겹침)은 빨간 표시 + 이유.
- 단원 사이의 빈 페이지(해설·정답 등)는 **계획에 넣지 않는다** (목차에 있는 페이지만 푼다).
- 표에서 **「계획에서 뺄 단원」** 을 체크할 수 있다 (예: 단원 정리, 부록).

### 4.3 목차 사진 읽기 (보조)

1. 「목차 사진으로 채우기」 → 사진 찍기/고르기 (여러 장 가능: 목차가 두 쪽일 때).
2. `readImageText()` 로 글자를 읽음 (기기 안에서만. 사진은 서버에 올리지 않음).
3. 읽은 글자를 §4.2 의 입력 칸에 넣고, 같은 규칙으로 표를 만든다 → 사용자가 확인·수정.

**아직 모르는 것 (만들면서 확인하고 그대로 보고한다):**
한글 목차를 tesseract `kor` 로 얼마나 정확히 읽는지. 정확도가 낮으면 이 기능은 「참고용으로 채워 주기」에 그치고, 기본은 직접 입력이다.
또 tesseract 언어 자료는 처음 쓸 때 인터넷에서 받으므로, **인터넷이 없으면 사진 읽기는 안 된다** (화면에 그렇게 알림).

### 4.4 진도 (어디까지 풀었나)

- 문제집마다 **푼 페이지 목록**을 범위로 저장한다: 예 `[[12,41],[60,62]]` (실제로는 기기 간 합치기를 위해 체크한 시각도 함께, §8.2).
- 입력 방법 3가지:
  1. 「오늘」 화면에서 오늘 분량 **체크** → 그 범위를 푼 것으로.
  2. **「p.__ 까지 풀었어요」** → 오늘 분량 시작부터 그 페이지까지.
  3. 문제집 화면에서 **단원·페이지를 직접 체크/해제** (순서 없이 풀었을 때).
- 계획보다 **더 풀면** 그만큼 이후 분량이 줄어든다. 덜 풀면 늘어난다 (§5.4).

## 5. 계획: 하루 분량 나누기 (핵심)

### 5.1 계획 만들 때 정하는 것

| 항목 | 기본값 | 설명 |
|---|---|---|
| 범위 | 문제집 전체 | 단원을 고르거나 페이지 범위 (예: 시험 범위 2~4단원) |
| 시작일 | 오늘 | |
| 마감 | (필수) | **시험**을 고르거나 **날짜 직접** |
| 마감 날 포함? | 시험이면 「전날까지」, 날짜 직접이면 「그날까지」 | 바꿀 수 있음 |
| 쉬는 요일 | 없음 | 공부 설정에서 한 번 정하면 모든 계획에 적용, 계획마다 바꿀 수도 있음 |
| 빼는 날짜 | 없음 | 〃 (여행·행사) |
| 과외 날 비율 | 50% | 과외 수업이 있는 날은 평소의 몇 % 만 배정 (0~100%, 공부 설정) |
| 하루 최대 | 없음 | 넘으면 경고만 (§5.5) |

**시험**은 따로 등록한다: 이름 + 날짜 (예: 「2학기 기말」 12/8). 「오늘」 화면 맨 위에 D-day 로 보인다. 계획들이 시험을 가리키므로, 시험 날짜를 바꾸면 그 시험에 맞춘 계획이 모두 다시 계산된다.

### 5.2 「공부하는 날」과 「무게」

마감까지의 날마다 무게를 정한다.

```
무게(날) = 0     … 쉬는 요일 / 빼는 날짜 / 마감 이후
         = 과외 날 비율 (예 0.5) … 그날 과외 수업이 있음 (§6, 휴강이면 아님)
         = 1     … 그 밖
```

### 5.3 나누는 방법 (순서대로, 쪼개지지 않게)

**남은 페이지**(범위 − 푼 페이지 − 과외 숙제로 잡힌 페이지 §6.2)를 앞에서부터 순서대로 늘어놓고, 무게에 비례해 날마다 잘라 준다.

1. 남은 페이지 수 `N`, 남은 날들의 무게 합 `W`.
2. 날마다 몫 `N × 무게 / W` 를 구하고, **큰 나머지 방식**으로 정수로 맞춘다
   (각 날 소수점 아래를 버리고, 남는 페이지는 소수점 아래가 큰 날부터 1쪽씩. 같으면 **앞날 먼저**).
   → 날짜별 페이지 수의 합이 정확히 `N`, 무게가 같은 날끼리는 차이가 최대 1쪽.
3. 페이지를 순서대로 잘라 붙인다: 첫날 1~8번째 페이지, 둘째 날 9~16번째 …
   (빠진 단원·푼 페이지는 건너뛰므로, 하루 분량이 「34~37, 40~43쪽」처럼 두 조각일 수 있다)
4. 날마다 **걸치는 단원 이름**을 붙인다: 「34~41쪽 · 2. 함수」, 단원 끝이면 「· 2단원 끝 🎉」.

**단원 끝 맞추기 (작은 보정):** 하루 분량의 끝이 단원 끝에서 **2쪽 이내**로 모자라거나 넘치면 단원 끝에 맞춘다
(다음 날 1~2쪽만 남는 일을 막음). 이 보정은 그 날과 다음 날 사이에서만 옮기므로 전체 합은 그대로.

### 5.4 밀렸을 때 · 더 했을 때 (자동 재분배)

계획을 **고정된 날짜표로 저장하지 않는다.** 언제나 「지금 남은 페이지 ÷ 지금부터 남은 날」로 새로 계산한다.
그래서 하루를 건너뛰면 그 양이 저절로 남은 날에 나뉘어 들어간다.

단, **오늘 분량은 오늘 처음 볼 때 정해서 저장(고정)** 한다. 오늘 공부하는 도중에 오늘 숫자가 바뀌지 않게 하려는 것.

```
오늘 처음 열 때:
  오늘 고정 분량 = 위 방법으로 계산한 「오늘」 몫 → 저장 (todayLock: {날짜, 페이지 범위})
오늘 중:
  고정 분량을 보여 줌, 체크하면 진도에 반영
  고정 분량보다 더 풀면 → 내일 이후 몫이 줄어듦 (오늘 몫은 그대로)
다음 날:
  어제 못 한 페이지는 「남은 페이지」에 그대로 있으므로 → 남은 날에 다시 나뉨
```

「오늘」 화면의 문제집 줄에는 **어제 못 한 것이 있으면 작은 글씨로 알려 준다**: 「어제 6쪽 밀려서 오늘부터 하루 1쪽씩 늘었어요」.

### 5.5 너무 많아질 때 (경고)

다음 중 하나면 문제집 줄에 ⚠ 와 함께 알려 주고, 고칠 방법을 버튼으로 준다.

- 하루 필요량이 **처음 계획한 하루 평균의 1.5배**를 넘음
- 하루 필요량이 **하루 최대**(설정했다면)를 넘음
- 마감까지 **공부하는 날이 0일** (마감이 지남 / 남은 날이 전부 쉬는 날)

고칠 방법: 「마감 늦추기」, 「쉬는 날 하루 공부하기」, 「범위 줄이기(단원 빼기)」, 「그대로 두기」.

### 5.6 문제집 화면에서 보여 줄 것

- 진도 막대: 푼 페이지 / 범위 페이지, 단원별 체크 상태.
- **달력 (이번 달·다음 달)**: 날마다 배정 페이지. 쉬는 날은 흐리게, 과외 날은 표시, 지난 날은 「한 양」.
- 「예정대로라면 오늘까지 ○쪽 → 실제 ○쪽 (○쪽 앞섬/밀림)」.
- 계획 수정·끝내기·지우기.

### 5.7 여러 문제집

문제집마다 따로 계산한다. 「오늘」 화면에는 **과목 순서 → 마감이 가까운 순서**로 쌓는다.
모든 문제집을 합친 하루 총량에 상한을 두는 기능은 1단계에서는 넣지 않는다 (써 보고 필요하면 추가).

## 6. 과외 숙제

### 6.1 과외 등록

| 항목 | 예 |
|---|---|
| 이름 | 수학 과외 |
| 과목 | 수학 |
| 수업 요일 | 화, 금 |
| 수업 시각 (선택) | 19:00 |
| 예외 | 휴강 날짜 · 보강 날짜(요일이 아닌 날 수업) |

**다음 수업일** = 오늘 이후 첫 수업일 (휴강 날짜는 건너뛰고, 보강 날짜는 넣음).
「오늘 이후」의 기준: 수업 시각이 있고 지금이 그 시각 전이면 **오늘 수업도 포함**, 아니면 내일부터.

### 6.2 숙제 넣기

- 「숙제 받았어요」 → 과외 선택 → 내용
  - **문제집 페이지** (가지고 있는 문제집 고르거나 이름만 쓰기) + 페이지 범위 — 여러 줄 가능
  - 또는 **글로 된 할 일** (예: 「단어 50개 외우기」, 「오답 정리」)
- **마감은 자동으로 다음 수업일** (바꿀 수 있음). 휴강을 나중에 넣으면 마감도 다음 수업일로 따라 바뀜 (직접 바꾼 마감은 그대로).
- 페이지 숙제는 §5 와 같은 방법으로 **오늘부터 마감 전날까지** 나눈다 (수업 당일까지로 바꿀 수 있음).
  과외 숙제에는 「과외 날 비율」을 적용하지 않는다 (숙제 자체가 과외 일).
- 숙제가 내 문제집의 페이지면, 숙제로 푼 페이지는 **그 문제집 진도에도 반영**된다 (같은 페이지를 두 번 배정하지 않음:
  숙제 범위는 문제집 계획에서 빠지고, 숙제로 풀면 문제집 진도가 올라감).

### 6.3 보이는 곳

- 「오늘」 화면 **맨 위**. 마감 지난 숙제는 빨간색 「밀린 숙제」.
- 과외 화면: 과외별로 「다음 수업 10/28(화) — 숙제 3개 중 2개 완료」, 지난 수업 숙제 기록.
- 수업 날 아침 「오늘 수업: 남은 숙제 1개」 줄.
- **질문 메모**: 숙제하다 모르는 문제를 숙제에 메모로 달 수 있다 (「p.37 5번 질문」) → 그 과외의 다음 수업 카드에 모아서 보여 줌.
  (사용자가 1차 답변에서 고르진 않았지만, 숙제 기능 안에 짧은 메모 칸 하나로 거의 비용 없이 들어가서 포함. 원하지 않으면 뺀다.)

## 8. 자료 저장과 기기 간 동기화

### 8.1 자료 모양 (하나의 묶음 `study`)

모든 항목은 `id`(무작위), `updatedAt`(고친 시각, 밀리초)를 가진다. 지운 항목은 바로 없애지 않고 `deleted: true` 로 남긴다(다른 기기에도 지운 걸 알리기 위해).

```ts
interface StudyData {
  v: 1;                                  // 자료 형식 버전
  settings: StudySettings & Stamp;       // 하루 시작 시각, 쉬는 요일, 빼는 날짜, 과외 날 비율, 하루 최대
  subjects: Record<Id, Subject>;         // { name, color, order }
  exams: Record<Id, Exam>;               // { name, date }
  books: Record<Id, Book>;               // { name, subjectId, units: {name, from, to, skip}[], totalPages?, done: [from,to,at][], undone: [from,to,at][] }
  plans: Record<Id, Plan>;               // { bookId, range, start, examId? | due?, includeDue, overrides, todayLock?, baseline }
  tutors: Record<Id, Tutor>;             // { name, subjectId, weekdays, time?, cancelled: date[], extra: date[] }
  homework: Record<Id, Homework>;        // { tutorId, given, due, dueManual, items: HwItem[], note }
  // 2단계
  notes: Record<Id, WrongNote>;          // 오답
  decks: Record<Id, CardDeck>;
  cards: Record<Id, MemoCard>;
  wordLists: Record<Id, WordList>;       // { name, kind: 'book'|'test'|'inbox', subjectId, days?, plan?, testDate?, newPerDay }
  // 단어 자체는 많아질 수 있어 따로 묶음 `words` 에 둔다 (§8.3)
  // 3단계
  sessions: Record<Id, StudySession>;    // 공부 시간 기록
}
type Stamp = { updatedAt: number; deleted?: true };
```

- 이 기기에는 `localStorage` 키 `ptcg-ko.study.v1` 에 저장 (사이트의 다른 키와 같은 이름 방식).
- 사진은 묶음에 넣지 않는다 (§8.4).
- **단어**는 따로 묶음 `words` (`ptcg-ko.study-words.v1`): `Record<Id, Word>`, `Word = { listId, term, meaning, day?, fromDict?, box, due, wrong, ...Stamp }`.
  단어 수천 개가 `study` 묶음을 크게 만들지 않게 나눈다. 합치기 규칙은 §8.2 와 같다 (단어마다 늦게 고친 쪽).

### 8.2 합치기 규칙

기존 챔피언로드·퍼즐과 같이 **합치기는 기기에서, 서버는 저장만** 한다.

- 항목별로 **`updatedAt` 이 더 큰 쪽**을 남긴다. 지운 표시도 하나의 「고침」이다.
- `updatedAt` 이 같으면 지운 쪽 → 그 밖엔 서버 쪽.
- **문제집 진도 `done`** 은 예외: 두 기기에서 다른 페이지를 체크했을 수 있으므로 **합집합**으로 합친다.
  체크 해제는 `undone: [from,to,at][]` (해제한 범위와 시각)로 기록해서, 해제 시각보다 뒤에 체크된 것만 남긴다.
- 지운 표시는 **60일 지나면** 정리한다 (그동안 모든 기기가 한 번은 맞췄다고 봄).
- 오늘 고정 분량(`todayLock`)도 항목의 일부라 같이 맞춰진다 → 폰에서 본 오늘 분량과 PC 의 오늘 분량이 같다.

### 8.3 서버 (worker/accounts.ts)

- `store/(challenge|analyses|puzzles)` 주소에 `study`, `words` 를 추가 → `store/study`, `store/words` GET/PUT. (기존 `blobs` 표 그대로)
- 단어 하나를 약 100자로 보면 1,800,000자 안에 **약 1만 5천 단어**. 넘을 것 같으면(1,500,000자) 「익힘」이 된 지 1년 넘은 단어의 기록을 줄이고, 그래도 넘으면 사용자에게 알린다.
- 묶음 크기 제한은 기존 1,800,000자(`MAX_REPLAY`). 글자 자료만 들어가므로 몇 년치도 이 안에 들어갈 것으로 보지만,
  **크기가 1,200,000자를 넘으면** 오래된 기록부터 줄인다: 끝난 계획의 날짜별 기록, 1년 넘은 공부 시간 기록, 해결 후 1년 넘은 오답.

### 8.4 사진 (오답 노트·목차)

- 기기에서 줄여서 저장: 긴 변 1600px, JPEG 품질 0.8 정도 → 한 장 **400KB 이하**가 되도록 (넘으면 더 줄임).
- 이 기기: IndexedDB `studyPhotos` 저장소.
- 로그인했으면 서버에도: 새 주소 `study-photo/<id>` (PUT/GET/DELETE), `blobs` 표에 이름 `photo:<id>` 로 저장.
- **사람마다 사진 300장까지** (넘으면 해결된 오답의 오래된 사진부터 지우자고 묻는다).
- 다른 기기에서는 사진을 **볼 때 받아 온다** (전부 미리 받지 않음).
- 목차 사진은 글자를 읽은 뒤 버린다 (저장 안 함).

**용량 근거와 확인 못 한 부분:** 로그인 서버는 Durable Object **하나**(`idFromName('global')`)에 모든 사람의 자료를 둔다.
Cloudflare 공식 문서의 SQLite Durable Object 제한은 **한 칸(문자열/BLOB/행) 2MB**이고(그래서 사진 한 장 400KB 는 여유가 있다),
**객체 하나의 최대 저장량은 문서 안에서도 10GB(제한 페이지) / 무료 플랜 1GB(FAQ)로 다르게 적혀 있어** 확인하지 못했다.
보수적으로 1GB 로 보고 사람마다 사진 한도를 둔 것이다. 친구 몇 명이 쓰는 규모라면 1GB 안에 들어간다.

### 8.5 로그인 안 했을 때 / 인터넷이 없을 때

- 로그인 안 함: 이 기기에만 저장. 공부 화면 위에 「로그인하면 폰·PC 에서 같이 볼 수 있어요」 한 줄 (닫을 수 있음).
- 나중에 로그인하면: 이 기기 자료와 서버 자료를 §8.2 규칙으로 합친다 (어느 쪽도 버리지 않음).
- 인터넷 없음: 그대로 쓰고, 연결되면 맞춘다 (기존 방식: 창으로 돌아올 때 / 바뀐 뒤 1.5초).
- 사이트 위 메뉴의 동기화 점(●)은 지금은 덱 동기화 상태만 보여 준다. 공부 자료 동기화 실패도 이 점에 반영한다.

## 9. 2단계: 오답 노트 · 암기 카드 · 영단어

### 9.1 다시 보기 간격 (오답·카드 공통)

상자 5개. 맞히면 다음 상자, 틀리면 1번 상자.

| 상자 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 다음에 볼 때까지 | 1일 | 3일 | 7일 | 14일 | 30일 |

- 5번 상자에서 맞히면 **「익힘」** (오답은 「해결됨」) → 더 안 나옴. 원하면 다시 넣을 수 있다.
- 이것은 Leitner 상자 방식을 단순하게 쓴 것이고, 간격 숫자는 **우리가 정한 값**이다 (연구에서 나온 정답 값이 아님). 설정에서 바꿀 수 있게 한다.
- 「오늘 복습」 = 다음 날짜가 오늘이거나 지난 것. 너무 많이 밀렸으면(예: 100개 넘음) 오늘은 오래 밀린 순으로 50개만 보여 주고 나머지는 내일로.

### 9.2 오답 노트

| 항목 | 설명 |
|---|---|
| 어디서 | 문제집 + 페이지 + 문제 번호 (문제집 체크하며 바로 넣으면 자동으로 채워짐) / 또는 직접 |
| 문제 | 글 또는 사진 (여러 장) |
| 내 답 · 정답 | 선택 |
| 왜 틀렸나 | 고르기: 개념 모름 · 계산 실수 · 문제 잘못 읽음 · 시간 부족 · 찍음 · 기타 + 한 줄 메모 |
| 과목 | 문제집에서 자동 |

- **다시 풀기**: 문제(또는 「쎈 p.37 5번」)만 보여 주고 → 직접 풀어 본 뒤 → 「맞혔어요 / 또 틀렸어요」 → 그 다음 정답·이유 표시. (§9.1 간격)
- 목록: 과목별, 「왜 틀렸나」별 개수 → 「계산 실수가 40%」처럼 나의 실수 습관이 보이게.
- 빨리 넣기: 「오늘」 화면에서 문제집 체크 → 「틀린 번호: 3, 7, 12」 → 오답 3개가 「쎈 p.34~41」 출처로 생성 (사진·이유는 나중에 채워도 됨).

### 9.3 암기 카드

- 카드 묶음(과목별) → 카드: 앞면 / 뒷면 (글자만, 1차).
- **한꺼번에 넣기**: 한 줄에 카드 하나, 앞뒤를 `|` 또는 탭 또는 ` - ` 로 구분. 엑셀·구글 시트에서 두 칸을 복사해 붙여도 됨(탭).
- 복습: 앞면 → 「답 보기」 → 「알았다 / 몰랐다」 (§9.1). 폰에서는 좌우로 밀어서도.
- 앞뒤 바꿔서 보기(뜻 → 단어) 선택.
- 영어 단어는 아래 §9.4~9.9 의 전용 기능을 쓴다 (암기 카드와 같은 상자 방식에, 단어장·단어 시험 계획과 객관식 퀴즈가 더해진 것).

### 9.4 영단어: 무엇을 외우나

사용자가 고른 세 가지 출처를 모두 다룬다. 모두 「단어 목록」 하나로 표현하고, 목록의 종류만 다르다.

| 종류 | 예 | 계획 |
|---|---|---|
| **단어장** (갖고 있는 책·**PDF**) | 「워드마스터 수능 2000」 Day 1~50 | 문제집처럼 **Day 단위로 하루 분량** (§9.6) |
| **단어 시험** (학교·학원) | 「학원 단어 시험 11/3 · Day 5~8」 또는 받은 목록 | **시험일까지** 새 단어를 나눠 익히고, 마지막 날은 전체 복습 (§9.6) |
| **모르는 단어 모음** | 문제 풀다·지문 읽다 만난 단어 | 계획 없음. 하루 새 단어 수만 정해 두고 들어온 순서대로 |

- **과외 단어 숙제**: 과외 숙제(§6.2)의 항목으로 「단어」를 고르면 단어 목록(새로 만들거나 단어장의 Day 범위)을 붙일 수 있다.
  마감은 다른 숙제처럼 다음 수업일, 하루 분량은 §9.6 단어 시험과 같은 방법으로 나눈다.
- 단어장은 **단어를 다 넣지 않아도** 쓸 수 있다: Day 수만 넣으면 「오늘 Day 7~8」 계획과 체크만 된다 (종이 단어장으로 공부할 때).
  단어를 넣은 Day 는 카드·퀴즈로도 외울 수 있다.
- **시판 단어장의 단어를 미리 넣어 두지 않는다.** 단어장 내용은 저작권이 있고 실제 내용을 확인할 수 없어서, 사용자가 직접 넣는다 (붙여넣기·사진).

### 9.5 단어 넣기

**⓪ PDF 파일 넣기 (단어장의 기본).** 사용자가 단어장 PDF(출판사 자료실의 단어 목록 PDF, 학원에서 받은 PDF 등)를 고른다.

1. PDF 는 **기기 안에서만** 읽는다. 서버에 올리지 않고, 다 읽으면 버린다 (단어·뜻만 저장).
   읽는 도구: Mozilla 의 **PDF.js** (`pdfjs-dist`, Apache-2.0, npm 최신 6.4.299 확인). 공부 화면에서 PDF 를 넣을 때만 불러온다.
2. **글자가 들어 있는 PDF** (대부분의 출판사·워드 파일 PDF): 페이지마다 글자 조각과 위치(x, y)를 꺼낸다.
   - 같은 높이(y)의 조각을 한 줄로 묶고, 왼쪽→오른쪽으로 잇는다.
   - **표처럼 칸이 나뉜 단어장**: 줄들의 x 위치를 모아 「단어 칸」·「뜻 칸」 경계를 찾는다 → 영어 칸 / 한글 칸으로 나눈다.
     **두 단(왼쪽 반·오른쪽 반)** 이면 왼쪽 단을 다 읽고 오른쪽 단을 읽는다.
   - `Day 3`, `DAY 03`, `3일차`, `Unit 3` 같은 줄은 Day 구분으로 본다.
   - 예문·발음기호(`[ǽpl]`)·파생어 줄은 기본으로 뺀다 (표에서 다시 넣을 수 있음).
3. **글자가 없는 PDF** (종이를 스캔한 PDF): 페이지를 그림으로 그려서 ②의 사진 읽기(tesseract)로 넘긴다.
   페이지가 많으면 오래 걸리므로 **읽을 페이지 범위를 고르게** 하고, 진행률과 「그만」 버튼을 둔다.
4. 결과는 ①과 똑같이 **표로 보여 주고 고친 뒤 저장**한다. 페이지·Day 별로 접어서 볼 수 있고,
   「이상한 줄」(뜻이 없음, 영어가 아닌 단어, 너무 긴 줄)은 빨간 표시.
5. 암호가 걸린 PDF 는 「비밀번호를 넣어 주세요」, 읽지 못하는 PDF 는 이유와 함께 「붙여넣기나 사진으로 넣어 주세요」.

**확인 못 한 것 (만들면서 실제 PDF 로 확인하고 그대로 보고한다):** 단어장 PDF 는 출판사마다 칸 배치가 달라서, 위 「칸 나누기」가 어떤 모양까지 맞게 읽는지는 실제 파일로 해 봐야 안다.
사용자가 가진 PDF 1~2개로 먼저 시험해서 맞추는 것을 만드는 순서에 넣는다 (§14).
PDF 의 저작권은 사용자의 것이 아니므로 사이트·저장소에 PDF 를 올리거나 다른 사람과 공유하는 기능은 넣지 않는다 (내 단어 목록으로만 저장).

**① 붙여넣기.** 한 줄에 단어 하나. 읽는 규칙:

```
apple 사과                 → apple / 사과
apple - 사과, 사과나무      → apple / 사과, 사과나무
1. give up 포기하다         → give up / 포기하다   (앞 번호는 지움)
abandon	(동) 버리다          → abandon / (동) 버리다 (엑셀·구글 시트에서 두 칸 복사 = 탭)
abandon: v. 버리다          → abandon / v. 버리다
Day 3                      → 이후 줄은 Day 3 (단어장일 때)
resilience                 → resilience / (뜻 비어 있음 → 직접 쓰거나 ③)
```

- 나누는 기준: 탭 → ` - `, `:`, `|` → 그 밖엔 **처음 나오는 한글(또는 `(`, `[`) 앞**에서 나눈다.
  영어 쪽에는 영문자·공백·`'`·`-`·`.`·`/` 만 남긴다 (`give up`, `well-known`, `a.m.` 같은 구·약어도 됨).
- 품사 표시(`n.`, `v.`, `(명)`, `[동]`)는 뜻 쪽에 그대로 둔다.
- 읽은 결과를 **표로 보여 주고** 고친 뒤 저장 (§4.2 와 같은 방식). 이미 그 목록에 있는 단어는 「중복」 표시.

**② 단어장 사진.** §4.3 과 같다: `readImageText()`(tesseract `kor`+`eng`, 기기 안에서만)로 읽고 → ①의 규칙으로 표를 만들고 → 사용자가 고친다.
영어 단어와 한글 뜻이 섞인 쪽 사진을 얼마나 정확히 읽는지는 **만들면서 실제 사진으로 확인하고 그대로 보고한다.**
두 단(칸)으로 된 단어장은 줄 순서가 섞일 수 있어, 사진을 한 단씩 잘라서 읽는 「자르기」 단계를 둔다.

**③ 단어만 쓰면 뜻 자동 (사전 제안).**

- 화면: 뜻이 빈 단어 옆에 「사전 뜻 보기」 → **뜻 후보를 최대 3개** 보여 주고 사용자가 고르거나 고쳐서 넣는다.
  **사용자가 고르기 전에는 저장하지 않는다.** 사전에서 온 뜻에는 작은 「사전」 표시를 남긴다.
- 사전에 없는 단어는 「사전에 없어요, 직접 써 주세요」. 뜻을 지어내지 않는다.
- **사전 자료는 아직 정하지 못했다. 만들기 전에 아래를 확인해서 통과한 자료만 쓴다.**

| 후보 | 알아낸 것 | 확인할 것 |
|---|---|---|
| 영어 위키낱말사전(Wiktionary)의 한국어 번역, wiktextract/kaikki.org 가 JSON 으로 뽑아 둔 자료 | kaikki.org 가 Wiktionary 를 JSONL 로 뽑아 내려받게 해 준다 | 이용 조건(Wiktionary 글은 보통 CC BY-SA·GFDL 로 알려져 있으나 이번에 공식 문서로 확인하지 못함), 한국어 번역이 달린 영어 단어 수, 뜻 품질 |
| 국립국어원 한국어기초사전 오픈 API | 사용 신청 후 인증키를 받는 방식, 「번역 포함」 선택이 있다(블로그 자료) | 한국어→영어 방향이라 영어 단어로 찾기에 맞는지, 이용 조건, 하루 요청 한도 |

- 확인 방법: 이용 조건을 원문으로 읽고(출처 표시 방법 포함), **자주 쓰는 영어 단어 200개**로 뜻을 뽑아 보고 틀린 뜻·이상한 뜻 비율을 세어 사용자에게 보여 준다.
- 쓰기로 하면: 빌드할 때 필요한 부분만 뽑아 **작은 파일 하나**(영어 단어 → 한국어 뜻 후보)로 만들어 사이트에 넣고, 「사전 뜻 보기」를 처음 누를 때만 받는다 (인터넷 없이도 그 뒤엔 됨, API 키 필요 없음). 사이트에 출처와 이용 조건을 표시한다.
- **두 후보 다 통과하지 못하면 ③은 빼고**, 뜻은 직접 쓰거나 ①·②로 넣는다. 그때는 사용자에게 그렇게 알린다.
- 참고: 이 작업 환경에서는 위 사이트들에 직접 접속하지 못했다 (네트워크 제한). 확인은 접속 가능한 환경에서 하거나, 사용자가 자료를 받아 올려 주는 방식으로 한다.

**④ 모르는 단어 빨리 넣기.** 「오늘」 화면과 공부 화면 어디서나 「＋ 단어」 → 단어(와 뜻) 한 줄 → 「모르는 단어 모음」에.
문제집을 체크할 때 「모르는 단어도 있었나요?」 한 줄도 둔다 (§7, 오답 넣기 옆).

### 9.6 하루 분량

- **단어장**: 단위가 페이지 대신 **Day**. §5 의 방법(무게, 큰 나머지, 밀리면 재분배, 오늘 고정, 경고)을 그대로 쓴다.
  쉬는 요일·빼는 날짜는 같고, 과외 날 비율은 단어장에 적용할지 설정에서 고른다 (기본: 적용 안 함, 단어는 짧게라도 매일 하는 편이 낫다고 보고).
  Day 대신 **단어 수**로 나누기도 고를 수 있다 (Day 마다 단어 수가 많이 다를 때).
- **단어 시험**: 범위 단어를 **시험 이틀 전까지** 새로 익히도록 나누고, **시험 전날은 범위 전체 복습**(§9.7 「시험 대비」).
  남은 날이 이틀이 안 되면 남은 날에 전부 나누고 경고한다.
- **모르는 단어 모음**: 하루 새 단어 최대 수(기본 10) 안에서 들어온 순서대로.
- 「새로 익힐 단어」와 「복습할 단어」(§9.1 상자 날짜가 된 것)를 따로 센다. 「오늘」 화면에는 둘을 합친 한 줄:
  `🔤 영단어  새 단어 30 · 복습 45   [시작]`

### 9.7 외우기와 퀴즈

**한 번 공부하기(세션)** = 오늘 새 단어 + 오늘 복습할 단어. 방식은 두 가지 (사용자가 고른 것):

1. **카드 넘기기**: 영어 → (떠올리기) → 「뜻 보기」 → 「알았다 / 몰랐다」. 뜻 → 영어 방향도 고를 수 있다. 폰은 좌우로 밀기.
2. **객관식 퀴즈**: 영어 단어와 **뜻 4개 중 하나** 고르기 (뜻 → 영어 4개 중 하나도 가능).
   - 틀린 보기(오답)는 **사용자가 넣은 다른 단어의 뜻**에서 고른다. 지어낸 뜻은 쓰지 않는다.
     같은 목록 → 같은 과목의 다른 목록 순으로 고르고, 품사 표시가 있으면 같은 품사를 먼저 고른다.
   - 정답과 글자가 같은 뜻, 정답 단어와 같은 단어의 뜻은 보기에서 뺀다.
   - 뜻이 있는 단어가 4개 미만이면 퀴즈는 안 하고 카드만.

**한 세션 안에서:** 몰랐던(틀린) 단어는 몇 장 뒤에 **다시 나오고**, 한 번 맞혀야 세션이 끝난다 (그날 안에 한 번은 떠올려 보게).

**다음에 볼 날 (§9.1 상자 사용, 단어용 규칙):**
- 처음 익힌 단어는 그 세션에서 맞히면 1번 상자로.
- 다음 복습에서 **카드로 「알았다」** → 다음 상자. **객관식으로 맞힘** → 다음 상자, 단 **3번 상자까지만** 오른다.
  4·5번 상자로 가려면 카드(뜻을 보지 않고 떠올리기)로 맞혀야 한다.
  — 이유: 보기 중에서 고르기는 스스로 떠올리기보다 쉽다. 이 규칙과 「3번까지」라는 숫자는 **우리가 정한 것**이다(바꿀 수 있음).
- 틀리면 1번 상자, 그 단어의 「틀린 횟수」 +1.

**시험 대비 (단어 시험의 전날, 또는 언제든 버튼으로):** 범위 전체를 상자와 상관없이 한 번씩 → 틀린 것만 다시 → 다 맞힐 때까지.
상자 기록은 바꾸지 않는다 (틀린 단어만 1번 상자로).

### 9.8 단어 목록 화면

- 목록별: 익힘(5번 상자 통과) / 익히는 중 / 아직 안 봄, Day 별 진도.
- **자주 틀리는 단어**: 틀린 횟수 많은 순 20개 → 「이것만 따로 공부」.
- 단어 고치기·지우기·다른 목록으로 옮기기. 목록을 텍스트로 내보내기(`단어<탭>뜻`, 다시 붙여넣기 가능).
- 같은 영어 단어가 여러 목록에 있으면 **목록마다 따로** 기록한다 (단어장과 학원 시험의 뜻이 다를 수 있으므로).

### 9.9 넣지 않는 것 (사용자가 고르지 않음)

- 스펠링 쓰기 시험, 발음 듣기: 이번에 고르지 않았다. 원하면 나중에 추가한다 (스펠링은 퀴즈 방식 하나를 더하는 정도라 작은 일).

## 10. 3단계: 공부 타이머 · 기록

- 「오늘」 화면 항목 옆 ▶ 또는 기록 탭에서 시작. 과목(또는 그 문제집)이 자동으로 붙는다.
- 방식: **뽀모도로** (기본 25분 공부 / 5분 쉬기, 4번마다 15분 쉬기, 모두 바꿀 수 있음) 또는 **스톱워치**.
- 타이머는 **시작 시각을 저장**해서 계산한다 → 화면을 끄거나 다른 앱에 갔다 와도, 새로고침해도 맞다.
  폰은 다른 앱에 가 있으면 소리·알림이 제때 안 날 수 있다(브라우저가 멈춤). 돌아오면 「25분 끝났어요 (3분 전)」으로 알린다.
- 끝나면 기록 저장: 과목, 문제집(있으면), 시작·끝, 실제 공부 분. 직접 넣기·고치기 가능.
- 보기: 오늘 / 이번 주 / 과목별 막대, 최근 4주 날짜별 칸(잔디). 과목별 **주간 목표 시간**(선택)과 비교.
- 기록은 숫자만 보여 주고 「잘했다 / 못했다」 판정은 하지 않는다 (§1.2: 시간이 곧 공부량은 아님).

## 13. 시험 (테스트) 계획

`npm test` (vitest) 로 돌리는 자동 시험. 꼭 들어갈 경우:

**allocate / plan**
- 40쪽, 무게 1인 날 5일 → 8쪽씩.
- 41쪽, 5일 → 9,8,8,8,8 (나머지는 앞날부터).
- 쉬는 요일·빼는 날짜에는 0쪽. 과외 날(0.5)은 평소의 약 절반.
- 페이지 합이 언제나 남은 페이지 수와 같다 (무작위 입력 200가지로 확인).
- 이틀 안 하면 남은 날 분량이 늘어난다. 더 하면 줄어든다.
- 오늘 분량은 오늘 중에 진도를 바꿔도 그대로 (고정).
- 단원 끝 2쪽 이내 보정이 합을 바꾸지 않는다.
- 마감 지남 / 남은 날 전부 쉬는 날 → 경고, 오류 없이.
- 푼 페이지·뺀 단원을 건너뛰어 하루 분량이 두 조각이 되는 경우.

**toc**: §4.2 의 줄 형식 전부, 줄표 종류, 점선, 로마 숫자 단원, 숫자 하나만 있는 줄, 뒤집힌 범위·겹침 표시.

**tutor**: 휴강 건너뛰기, 보강 포함, 수업 시각 전/후의 「오늘 수업 포함」, 직접 바꾼 마감 유지.

**dates**: 하루 시작 4시 (03:59 는 전날), 월말·연말·윤년.

**merge**: 늦게 고친 쪽 남기기, 지운 표시, 진도 합집합과 체크 해제, 60일 지난 지운 표시 정리, 오늘 고정 분량 맞추기.

**review (2단계)**: 상자 오르내리기, 5번 상자 → 익힘, 밀린 것 50개 제한.

**wordPdf (2단계)**: 글자 조각(위치 포함)을 넣어 줄 묶기, 두 칸(단어/뜻) 나누기, 두 단 순서, Day 줄, 발음기호·예문 빼기. 실제 단어장 PDF 1~2개로 결과 확인.

**wordParse (2단계)**: §9.5 ①의 줄 형식 전부, 탭 구분, 앞 번호 지우기, `give up` 같은 구, 품사 표시, `Day 3` 줄, 뜻 없는 줄, 중복.

**wordSession (2단계)**: 틀린 단어가 세션 안에서 다시 나옴, 객관식은 3번 상자까지만, 객관식 보기가 정답과 같은 뜻을 넣지 않음, 보기 후보가 4개 미만이면 퀴즈 안 함,
단어 시험 「이틀 전까지 새 단어 + 전날 전체 복습」 나누기, 시험 대비는 상자를 올리지 않음.

**timer (3단계)**: 새로고침 뒤에도 남은 시간, 뽀모도로 쉬는 시간 순서.

**화면 확인:** 만든 뒤 개발 서버를 띄워 브라우저(Playwright)로 폰 크기·PC 크기에서 「문제집 넣기 → 계획 → 오늘 체크 → 다음 날로 날짜 바꿔 재분배」를 직접 해 보고 화면을 찍어 확인한다.
**목차 사진:** 실제 한글 목차 사진으로 인식 결과를 확인하고 정확도를 있는 그대로 보고한다.

## 14. 만드는 순서 (1단계 안에서)

1. 계산부: `dates` → `pages` → `toc` → `allocate` → `plan` → `tutor` (시험 먼저)
2. 저장·합치기: `model`, `store`, `merge`, 서버 `store/study`, `accountSync`
3. 화면: 공부 탭 틀 → 문제집 넣기(직접 입력) → 계획 만들기 → 「오늘」 → 문제집 화면(달력) → 과외·숙제
4. 목차 사진 읽기
5. 사이트 연결: 메뉴·홈 카드·음악·카드 기다림 제외
6. 확인: `npm run typecheck`, `npm test`, `npm run build`, 브라우저로 화면 확인 → 커밋·푸시(자동 배포)

2·3단계는 1단계를 써 본 뒤 각각 작업 계획을 따로 세운다.
2단계 안에서는 영단어를 먼저 만들 수도 있다 (오답·암기 카드와 같은 상자 방식 `review.ts` 를 함께 쓰므로 순서만 바꾸면 됨). 순서는 사용자가 정한다.
